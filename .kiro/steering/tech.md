# Tech — SP500 Valuation Radar Mini

Companion steering: `code-style.md` (layout and style), `fail-closed.md`
(the fail-closed rule in full), `repo-hygiene.md` (public-repo red lines).

## Stack

- Python 3.11+, standard library first. No framework, no ORM, no global
  state. New third-party dependencies need a clear justification in the
  commit message; tests may use Hypothesis for property-based testing.
- Prices come only from Yahoo Finance's public chart endpoint — no API
  key, no credentials, no other network calls.

## Hard constraints

- **Completed closes only.** A tier may be triggered solely by the latest
  completed daily close. Intraday and pre-market quotes never count. A
  close that cannot be retrieved or is stale yields `no-data` for that
  ticker, never an estimate.
- **Fail closed, never fill in.** Missing data is reported, counted in the
  brief's coverage note (priced N of M anchors), and never estimated,
  carried forward silently, or generated by an AI. A partial run is never
  presented as an all-clear.
- **The classification engine is a pure function** of
  (close, trigger, fair_low): deterministic, no I/O, no globals. Tier
  precedence is fixed — red > fair-value zone > yellow > watch > ok — and
  the result also carries an `in_fair_range` boolean (the single primary
  tier is a deliberate simplification of the production two-dimension
  tracking; see design.md and the README disclosure).
- **Exit codes:** 0 = ran (any tier outcome); 2 = input/validation
  failure; 3 = zero tickers priced (total data failure — no brief is
  written as if the run were normal).
- **Testing:** the classification engine is covered by property-based
  tests (monotonicity, boundary inclusivity, tier exclusivity); CSV
  validation and the fail-closed price path get unit tests.
